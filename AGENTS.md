# atyrode/code — agent operating contract

`code` is a launch pad for oh-my-pi (`omp`): a Go binary whose dials pick a model
pool, a capability tier, a thinking depth and an advisor level, preview the exact
routing that selection produces, and then exec `omp` with that routing as a
one-shot `--config` overlay (`README.md`, `main.go`). It never edits an omp
configuration. Around the launcher sit a session registry, whole-session operator
worktrees, an account manager over the auth broker, a catalog generator, and
`code engine`, which launches native `omp --mode rpc` under a confirmed profile
for a supervising client such as atyrode/babel and reports its actual containment.
The launcher's final form is a manifold plugin (`docs/manifold-transition.md` §1);
`plugins/` is where that lands. `CLAUDE.md` points here and is never edited.

The marked common section is generated from
[dotfiles' engineering.md](https://github.com/atyrode/dotfiles/blob/main/modules/home/agents/engineering.md).
Edit Code's local sections outside it; propose reusable-rule changes at that
source. Dotfiles renders its own copies in the source PR. Here,
`.github/workflows/agent-policy.yml` checks exact generated bytes on PRs and main
pushes; hourly/manual synchronization renders the reviewed source into one bot PR,
verifies current-head core and policy CI, squash-merges when authorized and not
held, then dispatches main CI. It follows dotfiles main's automation code as well
as its policy, so both require consequential-source review. Updates have a normal
scheduling/CI window, not instantaneous consistency; running sessions keep their
loaded snapshot. This checked-in contract requires neither installed dotfiles
nor Codex and grants no personal standing merge permission.

## Commands and verification

| Command | Purpose and evidence |
| --- | --- |
| `scripts/gate.sh` | Core gate: gofmt drift, `go vet ./...`, then `go test ./...`. It disables CGO as release builds do and uses Go on PATH or `nix shell nixpkgs#go` when absent. Extra arguments reach `go test`; `scripts/gate.sh -run TestX` is a focused loop, not the full ready/merge gate. |
| `nix build .#omp --out-link /tmp/code-omp` | Build the runtime pin from `nix/omp.nix`; put `/tmp/code-omp/bin` on PATH for the native tool-registry canary. Use a run-owned output path and remove only that output link afterwards. |
| `CODE_REQUIRE_SANDBOX=1 CODE_TEST_REQUIRE_OMP=1 scripts/gate.sh` | Require both real containment and the real OMP canary locally, with the prerequisites below. |
| `CGO_ENABLED=0 go build -o /tmp/code .` | Build the executable to drive through the changed CLI or terminal path; `code` on PATH is the installed release, not this build. Use a run-owned binary path and clean it up. |
| `code generate init` | Scaffold `models.yml` from `omp models/usage/bench --json`; this probes real models and takes minutes, not an offline fixture command. |
| `code generate --models-file F --out /tmp/grid.plain` | Render a catalog; `--out -` writes stdout. A file without `probed: true` is refused. |
| `CODE_OMP_SMOKE=1 go test -run 'TestOmpSmoke$' -v ./` | Separate upstream-drift smoke: effective overlay, JSON schemas and role inventory. Opt-in locally; `omp-smoke.yml` runs weekly/manually against latest upstream and opens or updates one `omp-drift` issue on failure. |
| [Plugin gate](plugins/README.md#commands) | Apply for plugin changes, with the pinned sibling SDK and both real-server modes described below. |

The Linux containment escape scenarios (`sandbox_linux_test.go`) need bubblewrap,
a working user systemd session with transient scopes/resource controls, and
unprivileged namespace creation. Local absence produces an `UNVERIFIED` message
on stderr and skips; `CI` or `CODE_REQUIRE_SANDBOX=1` makes absence fail. Do not
opt required evidence out. The real OMP tool-registry canary (`omptools_test.go`)
uses `omp` on PATH, reports an unverified skip if unavailable, and fails with
`CODE_TEST_REQUIRE_OMP=1`; the gate sets that flag in CI. These are distinct
measurements: containment, the pinned native registry, and the optional
latest-upstream drift smoke do not substitute for one another.

`.github/workflows/ci.yml` runs the equivalent core commands, not literally the
script. It provisions bubblewrap, user-session linger and the runner's namespace
permission, checks their composition, and installs the OMP pin from `nix/omp.nix`.
That pin also owns the `#with-omp` bundle; OMP is a runtime dependency, not a Code
build dependency. A locally skipped native measurement remains unverified unless
identified CI evidence supplies it. Ready/merge needs the applicable complete
checks, including plugin CI when its paths change; an honest incomplete draft
checkpoint may be published with its failed or unrun criteria stated.

### Headless transition and terminal proof

From 2026-09-05, nothing new is built TUI-bound that is not also reachable
headless (`docs/manifold-transition.md` §1). A capability that would land in
`update.go` lands first in a headless verb or a `code.*` door; a rendering that
would land in `view.go` waits for its plugin surface. A facet — catalog data plus
one overlay key rendered by the existing dials — is allowed; a new Bubble Tea
surface is not. The TUI stays until its plugin replacement is proven end to end.

Changes to `view.go`, `layout.go`, `render.go` or glyph tables require the
`tui-visual-verification` skill (available under `~/.agents/skills` in the operator
setup): actual interaction and rendered terminal capture at fixed dimensions,
including affected transitions. Render-function tests are not terminal proof.
For a freshly built `/tmp/code`, the complete golden catalog supplies real routing
without a broker:

```sh
SESSION="tui-$$"
tmux new-session -d -s "$SESSION" -x 150 -y 44 \
  "env -u NO_COLOR -u CI CLICOLOR_FORCE=1 COLORTERM=truecolor TERM=xterm-256color \
   CODE_GENERATED=$PWD/testdata/two-pool-golden.plain CODE_SELECTION_STATE=off \
   CODE_SESSION_STATE=off /tmp/code; sleep 300"
tmux send-keys -t "$SESSION" Down Right                  # drive a dial
tmux capture-pane -t "$SESSION" -pe > /tmp/frame.ansi    # SGR; -p for plain text
tmux kill-session -t "$SESSION"                         # only your session
```

Use run-owned capture paths and tear down the session on failure too; never use
`kill-server`. Nerd Font glyphs use Private Use Area codepoints: inspect the
capture for the intended codepoint and use the skill's visual checks. Catalog
changes also use `testdata/two-pool-golden.plain` (`TestGoldenCatalogTwoPool`);
re-record it deliberately and review the change, never merely to make a test pass.

## Issues, worktrees and delivery

- Every planned code or user-visible documentation change starts from a GitHub
  issue with the problem and acceptance criteria. Transition work carries the
  `manifold-transition` label. The approved generated-only policy bot is
  mechanical source maintenance and does not need a fresh issue per propagation.
- Work in your own isolated worktree and branch from `origin/main`, never a shared
  checkout. `code wt` and a hand-made git worktree are both valid. Before editing,
  inspect open PRs and their files/bodies (`gh pr list --state open`, then
  `gh pr view N --json files,body`): scopes can claim a ledger row, a `CODE_*` name
  or a documentation hunk as well as a file. Coordinate through issue/PR comments,
  never by pushing to someone else's branch; never force-push a branch you did
  not create.
- Keep changes small and coherent, with conventional commit prefixes
  (`ci(plugins):`, `docs:`, `chore:`). Rebase onto main before the full integration
  gate; the integration owner checks the combined result. Do not reformat
  unrelated text, particularly shared README and AGENTS hunks.
- Target main and link the owning issue: `Closes #N` only for its complete
  acceptance, otherwise `Refs #N` with remaining work named. Use authorized squash
  merge and delete the branch after current required CI and acceptance pass.
- `docs/manifold-transition.md` §6 is the only transition progress ledger. The PR
  moving a step (`not started` → `in progress` → `shipped` → `proven`) updates its
  row; nothing else does. Consult `docs/status.md` for dated caveats, not a second
  progress map, and do not describe planned or unpublished native work as shipped.

## Ownership and compatibility invariants

The maintained command/environment/state descriptions are in
`docs/configuration.md`, the launcher map and decisions in
`docs/manifold-transition.md`, and current implementations in their owning source.
Do not duplicate their full maps or version inventory here.

1. **OMP owns the runtime.** Ordinary-session retry, model fallback, quota
   enforcement, sandboxing, resume and in-session subagent worktrees belong to
   OMP. Code owns pre-launch estimates, the capability ladder, reachability probes,
   whole-session operator worktrees and the cross-launch registry. The provider,
   pool and lane registry is `routing.go`/`providers.go`; do not hard-code parallel
   provider IDs, pool letters or buckets elsewhere.
2. **One-shot overlays.** Each launch uses an ephemeral `--config` overlay; never
   write the operator's OMP configuration. Dials setting OMP switches put values
   where OMP reads them (`launch.go`, `docs/configuration.md`). Forwarded launcher
   arguments retain their contract, including verbatim `--continue` and the
   launcher's replacement of a forwarded `--profile` (`main.go`).
3. **Native engine evidence.** `code engine` resolves an operator-confirmed
   immutable profile and forwards OMP's native RPC, with provider credentials
   redacted, including `rpc_chunk` frames (`engine.go`, `engineredact.go`). The
   atomic, mode-0600 `code.runtime/1` report exists before the first forwarded byte
   and is rewritten with exit status/resource use afterwards. Its containment
   declaration must match the probed and established boundary (`sandbox.go`,
   `sandbox_linux.go`); missing required containment is a refusal, not permission
   to weaken the declaration or escape scenarios. `--describe` is profile
   metadata, not containment/runtime proof. Closing stdin ends the child tree.
   Profile dials come from the operator's terminal ceremony, not environment or
   argv overrides; configuration without a terminal is refused.
4. **Credential ownership.** Broker tokens travel only in the environment
   (`vault.go`, `withAuthEnv`). Untrusted, runtime and broker-less launches strip
   every `OMP_AUTH_BROKER_*` key and `CODE_AUTH_ACCOUNT_STATE` (`withoutAuthEnv`).
   The DeepSeek API key remains in memory, never serialized. The account pool is
   mode 0600 in a mode-0700 pid-tagged temporary directory, swept after its session.
   Launcher secrets remain on the machine, never in Manifold; launch authority
   stays on the spoke (`docs/manifold-transition.md`, D2/D5).
5. **External wrapper and persistent contracts.** CLI and `CODE_*` compatibility
   protects separately released callers, notably dotfiles' `codeLauncher`, which
   owns personalization, catalog, broker and vault wiring. Change these only with
   coordinated downstream migration, not a blanket internal no-shims rule.
   Preserve recorded profile references and immutable revision numbers;
   `--import-profiles` copies exact revisions, rejects conflicting content and
   leaves the source store untouched. Legacy worktrees remain discoverable and
   removable; no silent relocation or migration. Internal cutovers migrate every
   caller and remove obsolete paths, but do not delete public or persistent-format
   migration/rollback support before its coordinated transition is complete.
   Keep the `ctrl+o` default model aligned with cli-kit's `ollama.DefaultModel` and
   dotfiles' `localClassifier.model`.
6. **State and session privacy.** Code worktrees live under Code's state root,
   never OMP's: `omp worktree clear --all` cannot see Code's liveness registry.
   OMP owns writes to its own session store. `history.go` reads only leading
   title/session metadata (id, timestamp, cwd, title), never conversation bodies,
   prompts or tool output, and never searches untrusted `ompu` roots. State paths,
   overrides and resume behavior are owned by `docs/configuration.md` and
   `worktree.go`/`history.go`, not a second root-file inventory.
7. **Provider degradation.** Support the Anthropic/OpenAI setup; fewer configured
   providers must not crash the launcher. Unconfigured features hide themselves
   (`docs/status.md`).
8. **Offline test seams.** Ordinary tests are deterministic and offline: generator
   probe variables (`ompModelsJSON`, `ompUsageJSON`, `ompBenchJSON`), fake `CODE_OMP`
   scripts or test-binary re-exec, and `httptest` broker/balance servers. The real
   containment, native canary and opt-in drift lanes are the explicit exceptions
   in Commands and verification, not permission for incidental live probes.
9. **Small dependencies.** Prefer the current small Go dependency set. Additions
   must justify a real need, maintenance cost and compatibility consequences; Nix
   outputs wrap published binaries rather than adding Code build dependencies.

## Manifold plugins

`plugins/` contains `atyrode.code` and its part `atyrode.code.generator`.
`plugins/README.md` owns the command gate and bundle details; Manifold's
`docs/PLUGINS.md` §9 owns the kit. Code adapts to Manifold: missing platform
capabilities become Manifold issues, not a second mechanism here.

- An isolated Code worktree is valid when its sibling `../manifold` is checked out
  at `plugins/MANIFOLD_REV`. The plugin TypeScript paths resolve to that sibling
  from `plugins/`. Run `bun install --frozen-lockfile` in both the sibling SDK and
  Code's `plugins/`. Bump `MANIFOLD_REV` and the reusable-workflow ref in
  `.github/workflows/manifold-plugins.yml` atomically.
- The plugin gate checks, tests, packs and verifies against disposable real hubs:
  install both bundles normally and hardened, dispatch every door, uninstall in
  each mode. Normal server admission does not prove a Worker-authored panel can
  mount; the panel requires hardened installation. Bundle/source verification is
  not installed-browser proof. These checks apply before ready/merge, not before
  every incomplete draft push.
- For an authorized integrated-preview iteration, this practical command runs
  from the host with access to the actual preview container; inspect its current
  configuration and live enrolled-machine roster rather than assuming a named
  host is online:

  ```sh
  bun run dev -- --hub http://127.0.0.1:7912 --deliver docker:manifold-dev-manifold-1
  ```

  From `plugins/`, it packs, installs parents before parts in hardened mode, then
  watches and reinstalls. Inspect `https://preview.manifold.tyrode.dev` → plugin
  manager → Installed → `atyrode.code` / `atyrode.code.generator`; launch requires
  a machine currently online on that hub. A browser reload shows the installed
  change, not merely a local bundle build.
- At the end of plugin work and whenever asking the operator to look, give the
  actual hub URL, panel, action and expected result, naming a currently observed
  machine. Preview mutation needs the task's authority; production
  (`https://manifold.tyrode.dev`) is operator-only, installed by hand from the
  release URL in the plugin manager, root only, never automated.
- The owner key never enters argv, logs or committed files. `dev` reads it from
  the container or `--owner-key-file`; do not copy credentials between machines.

## Releases

A `v*` tag is publication, not proof every installed client updated.
`.github/workflows/release.yml` publishes static `CGO_ENABLED=0` Go binaries for
Linux/Darwin × amd64/arm64, then packs plugins against `plugins/MANIFOLD_REV` and
attaches `dist/*.manifold-plugin.json` plus `SHA256SUMS`. If `DEV_DEPLOY_HOST` is
configured, the receiver installs bundles from release URLs into the integrated
preview, parents before parts, explicitly hardened. Before release, verify the
receiver supports Manifold #364 as required by `plugins/README.md`; an SDK pin
does not update the receiver. A tag can therefore cause preview mutation and
requires the corresponding release authority. Production installation remains
the operator's separate action described above. Downstream dotfiles pin updates
and machine activation are separate evidence, with no update-time guarantee here.

After GoReleaser finishes, run `scripts/bump-flake-pin.sh <tag>` and PR the result.
The flake wraps published binaries, not a source build (`flake.nix`, `nix/code.nix`);
`nix run github:atyrode/code` serves the new version only after that pin changes.

Never move or delete a published tag: Go module proxies/checksum records make
versions immutable. Leave a bad tag in place and publish the next patch.
For day-to-day cli-kit iteration, use
`go get github.com/atyrode/cli-kit@<sha>` (a pseudo-version) and let cli-kit tag
milestones; the same tag-immutability rule applies there.
